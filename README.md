## 核心架构决策

### 1) 数据真源
- 运行态真源是 `SQLite`。
- `YAML(config/*)` 只用于导入初始化和导出备份。
- 前端与业务运行态不直接写 YAML。

### 2) 三道门槛（Gate）
- `Gate-A 可复现`：新机器 5 分钟按文档跑通核心闭环。
- `Gate-B 契约稳定`：核心接口只增不减，不改语义。
- `Gate-C 降级可用`：外部源失败时按基金粒度降级，页面仍可用。

### 3) 前后端职责
- 后端：认证、隔离、计算、审计、存储。
- 前端：任务导向工作台、可视化、交互编排。
- 通过 API 契约协作，不跨层写入。

## 当前产品方向（阶段二）
- 多用户登录与数据隔离（已启动）。
- 持仓中心优先于四船看板，信息高密度且可操作。
- 统一设计系统（Token 化）和页面交互标准。
- 自动刷新、提醒、交易链路、消息中心逐步接入。
