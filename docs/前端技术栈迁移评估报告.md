## 二、Ant Design 迁移可行性评估

### 2.1 技术兼容性

| 检查项 | 状态 | 说明 |
|--------|------|------|
| React 18 兼容 | ✅ 通过 | antd 5.x 完全支持 React 18 |
| Vite 构建 | ✅ 通过 | antd 提供 Vite 插件支持 |
| TypeScript | ⚠️ 需注意 | 项目当前为 JSX，迁移需考虑 TS 升级 |
| CSS-in-JS | ✅ 通过 | antd 5.x 使用 CSS-in-JS (emotion) |

### 2.2 迁移成本评估

#### 需要重写的组件

| 组件 | 复杂度 | 建议替代 Antd 组件 | 预估工时 |
|------|--------|-------------------|----------|
| `TopToolbar` | 高 | `Layout.Header` + `Input.Search` + `Dropdown` | 4h |
| `BottomTabs` | 中 | `Tabs` 或自定义 TabBar | 2h |
| `HoldingsTable` | 高 | `Table` + `Tag` + `Button` | 6h |
| `SettingsDrawer` | 高 | `Drawer` + `Form` + `Switch` + `Select` | 4h |
| `LoginPanel` | 中 | `Form` + `Input` + `Button` + `Card` | 2h |
| `SIPPlanManager` | 中 | `Table` + `Modal` + `Form` | 4h |
| `SummaryCards` | 低 | 直接复用现有 CSS | 0.5h |
| `DataStatusBanner` | 低 | `Alert` + `Tag` | 1h |
| `RiskStatusBar` | 中 | `Progress` + `Tag` | 2h |
| `StateShowcase` | 低 | 展示组件，可保留 | 0.5h |

**总计重写组件数**: 10 个核心组件  
**可直接复用组件**: 17 个 (主要是图表和逻辑组件)

### 2.3 包体积影响分析

| 方案 | 构建产物估算 | 增量 |
|------|--------------|------|
| 当前方案 | ~150 KB (gzip) | - |
| antd 完整引入 | ~400-500 KB | +200-350 KB |
| antd 按需引入 | ~250-300 KB | +100-150 KB |
| antd + tree-shaking | ~200-250 KB | +50-100 KB |

**优化建议**: 使用 `@ant-design/vite-plugin` 实现按需加载 + CSS tree-shaking

### 2.4 主题定制能力

#### 品牌色融合方案

Antd 支持通过 `ConfigProvider` 定制主题，与现有品牌色系的映射：

```jsx
<ConfigProvider
  theme={{
    token: {
      colorPrimary: '#4361ee',  // 现有 --color-accent
      colorSuccess: '#10b981', // 现有 --color-success
      colorWarning: '#f59e0b',  // 现有 --color-warning
      colorError: '#ef4444',   // 现有 --color-error
      borderRadius: 12,        // 现有 --radius-button
      fontFamily: "'Noto Sans SC', sans-serif",
    },
    components: {
      Table: {
        headerBg: '#f7f8fa',
        rowHoverBg: '#f1f5f9',
      },
      Card: {
        borderRadiusLG: 16,  // 现有 --radius-card
      },
    },
  }}
>
```

**结论**: ✅ 主题定制完全可行，CSS 变量可与 Antd Token 共存

### 2.5 风险评估

| 风险项 | 等级 | 缓解措施 |
|--------|------|----------|
| 全局样式冲突 | 中 | 使用 CSS Module 隔离，迁移期间保留 index.css |
| 交互行为差异 | 中 | 逐一对比验收，保留必要自定义交互 |
| 第三方依赖冲突 | 低 | Antd 为独立依赖，无已知冲突 |
| 升级回退成本 | 中 | 使用功能开关渐进式迁移 |

## 三、金融图表库评估

### 3.1 当前方案分析: Chart.js

**优势**:
- 轻量级 (~200KB)
- 上手简单
- 已集成到现有项目

**劣势**:
- 金融专用图表支持弱
- 无 K 线图、成交量图等专业功能
- 交互定制受限
- 大数据量渲染性能一般

### 3.2 竞品对比

| 维度 | Chart.js (当前) | ECharts | react-financial-charts |
|------|-----------------|---------|------------------------|
| 包大小 | ~200KB | ~300KB | ~150KB |
| K 线图 | ❌ 需自定义 | ✅ 原生支持 | ✅ 专业支持 |
| 成交量图 | ⚠️ 需自定义 | ✅ 原生支持 | ✅ 专业支持 |
| 股票指标 | ❌ 无 | ⚠️ 基础 | ✅ 丰富 |
| 交互能力 | 中 | 强 | 强 |
| React 集成 | react-chartjs-2 | echarts-for-react | react-financial-charts |
| 社区活跃度 | 高 | 极高 | 中 |
| 文档质量 | 好 | 优秀 | 良好 |
| 学习曲线 | 低 | 中 | 中 |
| 定制灵活性 | 中 | 高 | 高 |

### 3.3 推荐方案

#### 推荐: **ECharts**

**推荐理由**:

1. **金融图表专业**: 原生支持 K 线图、MACD、RSI、成交量等金融指标
2. **性能优秀**: Canvas 渲染优化良好，支持大数据量
3. **交互丰富**: 缩放、拖拽、数据区域选择等
4. **社区活跃**: Apache 顶级项目，长期维护有保障
5. **中文友好**: 阿里开源，文档和社区以中文为主
6. **扩展性强**: 支持自定义 series 和 renderItem

**备选方案**:

- **react-financial-charts**: 如果未来需要股票交易功能，可作为补充
- **Recharts**: 如果保留 Chart.js 风格，可考虑迁移到更 React 友好的库

### 3.4 ECharts 集成方案

```jsx
import ReactECharts from 'echarts-for-react'

// 收益曲线图示例
<ReactECharts
  option={{
    tooltip: { trigger: 'axis' },
    xAxis: { type: 'category', data: labels },
    yAxis: { type: 'value', axisLabel: { formatter: '{value}%' } },
    series: [
      {
        name: '累计收益率',
        type: 'line',
        data: values,
        itemStyle: { color: '#4361ee' },
        areaStyle: { opacity: 0.1 }
      }
    ]
  }}
  style={{ height: '200px' }}
/>
```
