# 部署与运行（VectorControl）

## 1. 本地开发
### 1.1 环境要求
- Python 3.11+
- Node.js 18+
- npm 9+
- Docker Desktop（用于 Gate-D 本地验证）

### 1.1.5 Windows 一键启动（可选）
如果使用 Windows PowerShell，可以使用一键启动脚本：

```powershell
# 在项目根目录执行
.\scripts\dev_up.ps1
```

该脚本会：
1. 自动创建后端虚拟环境（如果不存在）
2. 安装后端依赖并启动 uvicorn（端口 21345）
3. 安装前端依赖并启动 Vite（端口 5173）
4. 自动检查服务健康状态

停止服务：
```powershell
.\scripts\dev_down.ps1
```

### 1.2 启动后端（手动）
建议开 2 个终端窗口：后端 1 个、前端 1 个。

Windows（PowerShell）示例：
```powershell
cd <local>\VectorControl
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 21345
```

macOS/Linux（bash）示例：
```bash
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 21345
```

### 1.3 启动前端
说明：`frontend/vite.config.js` 会将 `/api/*` 代理到 `http://127.0.0.1:21345`，所以后端需先启动。

Windows（PowerShell）示例（推荐使用 `--strictPort` 避免端口自动漂移导致联调误判）：
```powershell
cd <local>\VectorControl
npm --prefix frontend install
npm --prefix frontend run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

macOS/Linux（bash）示例：
```bash
cd frontend
npm install
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

访问地址：
- 前端：`http://127.0.0.1:5173`
- 健康检查：`http://127.0.0.1:21345/api/healthz`（兼容：`/api/health` 仍可用）

### 1.4 如何停止服务/如何查看日志（本地，Windows 适用）
- 停止服务：在后端/前端各自的终端窗口按 `Ctrl + C`。
- 查看日志：
  - 后端：启动 uvicorn 的终端输出即为运行日志。
  - 前端：启动 Vite 的终端输出 + 浏览器 DevTools 的 `Console/Network`。
- 常见问题：端口被占用
  - 查看占用：`netstat -ano | findstr :21345` / `netstat -ano | findstr :5173`
  - 结束进程：`taskkill /PID <pid> /F`

## 2.1 发布前文档门禁（main）
在 `dev -> main` 前执行以下检查：

1. 核对并必要时更新：
   - `README.md`
   - `ROADMAP.md`
   - `docs/架构说明.md`
   - `docs/开发规范.md`
   - `docs/接口契约.md`
   - `docs/交易流水YAML导入规范.md`
   - `docs/P0线上故障排查SOP.md`
   - `docs/状态解释验收样例.md`
   - `docs/最新进度.md`
   - `docs/Git工作流.md`
   - `docs/部署与运行.md`
2. 确认文档与本次代码改动一致，无过期描述。
3. 执行发布前一键预检：`python scripts/check_release_preflight.py`（默认包含文档门禁严格模式、后端 compileall、前端 build）。
4. 如需只检查文档门禁，可单独执行：`python scripts/check_docs_gate.py`。
5. 发布说明必须包含 `新增/修复/优化/文档` 四段。
6. push 前确保已启用 `.githooks/pre-push`（需要时执行 `git config core.hooksPath .githooks`）。
7. PR 到 `dev/main` 时，云端 `Docs Gate` 工作流会再次校验文档门禁。
8. `main` 发布后执行：`python scripts/check_main_release.py --commit HEAD --check-remote-tag --remote origin`。

## 3. VPS 生产部署（Gate-D）
方案：`Nginx + Docker Compose + backend + postgres`  
原则：公网仅开放 `80/443`，后端与数据库仅容器内通信。

### 3.1 前置条件
- Linux VPS（推荐 Ubuntu 22.04+）
- 已安装 Docker 与 Docker Compose
- 若启用 HTTPS，域名 A 记录已指向 VPS
- 防火墙开放 `80/443`

### 3.2 环境变量
```bash
cp deploy/.env.example deploy/.env.prod
```

最小必填：
- `VC_DOMAIN`：域名或 `127.0.0.1`
- `VC_EMAIL`：证书邮箱
- `API_TOKEN`：后端访问令牌
- `POSTGRES_PASSWORD`：数据库密码

部署模式：
- HTTP 最小闭环：`VC_ENABLE_TLS=false`
- HTTPS 生产模式：`VC_ENABLE_TLS=true`

### 3.3 首次部署（3 条命令）
```bash
cp deploy/.env.example deploy/.env.prod
# 编辑 deploy/.env.prod
bash scripts/deploy_prod.sh
```

### 3.4 Gate-D 验收
HTTP 最小闭环：
```bash
VC_DOMAIN=127.0.0.1 VC_SCHEME=http python scripts/check_gate_d.py
```

HTTPS 生产验收：
```bash
VC_DOMAIN=your.domain VC_SCHEME=https python scripts/check_gate_d.py
```

如需同时校验“网络测速接口”可用性（推荐）：
```bash
VC_DOMAIN=your.domain VC_SCHEME=https VC_BENCHMARK_TOKEN=<token> python scripts/check_gate_d.py
```
或使用账号密码：
```bash
VC_DOMAIN=your.domain VC_SCHEME=https VC_BENCHMARK_USERNAME=admin VC_BENCHMARK_PASSWORD='***' python scripts/check_gate_d.py
```

通过标准：
1. `/<首页>` 返回 200 且包含 `VectorControl`。
2. `/api/healthz` 返回 200。
3. 未登录访问 `/api/auth/me` 返回 401（旧版回退校验 `/api/config` 401）。
4. `nginx/backend/postgres` 容器都处于 running。
5. （提供测速校验凭证时）`/api/settings/network-benchmark/latest` 返回 200。

### 3.8 Gate-D 验收证据留档（强制）
每次 `main` 发布后，完成验收并沉淀证据，使用模板：

- `docs/Gate-D验收证据模板.md`

建议最小流程：
1. 执行发布一致性校验：
   - `python scripts/check_main_release.py --commit HEAD --check-remote-tag --remote origin`
2. 执行 Gate-D 验收：
   - `python scripts/check_gate_d.py`（按环境参数）
3. 记录容器状态与 commit：
   - `git rev-parse --short HEAD`
   - `docker compose -f deploy/docker-compose.prod.yml ps`
4. 将截图/命令输出填入模板并存档。

## 4. 回滚
1. 切回目标提交：
```bash
git checkout <commit_or_tag>
```
2. 重新拉起容器：
```bash
docker compose --env-file deploy/.env.prod -f deploy/docker-compose.prod.yml up -d --build
```
3. 再次执行 Gate-D：
```bash
VC_DOMAIN=your.domain VC_SCHEME=https python scripts/check_gate_d.py
```

## 5. 安全说明
- 只暴露 `80/443`；不要暴露 `5432` 或后端内部端口。
- 不要提交 `deploy/.env.prod`、`deploy/certbot/`、`deploy/data/`、`deploy/backups/`。
- 定期轮换 `API_TOKEN` 与数据库密码。

## 6. 常见问题
### 6.1 `docker: command not found`
未安装 Docker，请先安装 Docker Engine 与 Compose 插件。

### 6.2 `check_gate_d.py` 报编码错误
已在脚本中做 UTF-8 容错；如仍异常，请确认系统 Python 与 shell 编码一致。

### 6.3 HTTPS 签发失败
- 检查域名解析是否正确。
- 检查 80 端口是否被防火墙或其他服务占用。
- 检查 `VC_EMAIL`、`VC_DOMAIN` 是否填写正确。

### 6.4 测速 `Not Found` 或设置中心白屏
- 标准排查流程见：`docs/P0线上故障排查SOP.md`。
- 关闭故障前需补齐：根因、修复提交、回归证据、Gate-D 留档链接。
