# 接口契约（VectorControl）

> 契约原则：允许新增字段，不允许删除字段或改变语义。

## 0. 健康检查
### `GET /api/health`
- 出参：`ok`、`service`

### `GET /api/healthz`
- 出参：`status`、`service`

### `GET /api/system/status`
- 语义：系统自省快照（需登录态）
- 出参顶层：
  - `service`、`version`、`commit`、`server_time`、`python_version`
  - `release`：
    - `current`：`version`、`commit`
    - `online_reference`：`version`、`commit`、`source`（`env/git_ref/unknown`）
    - `compare_with_online`：`status`（`same/ahead/behind/diverged/unknown`）、`ahead`、`behind`
  - `user`：`user_id`、`username`、`is_admin`、`holdings_scope_user_id`、`snapshot_scope_user_id`
  - `snapshot`：
    - `estimate_snapshot`：`available`、`asof`、`updated_at`、`confirm_state`
    - `fund_catalog`：`active_count`
    - `fund_nav_daily`：`record_count`、`latest`
    - `fund_sync_job`：最近同步任务（可为 `null`）
    - `actions_log`：最近动作摘要
    - `transactions_sync_pending`：`available`、`last_run_at`、`latest_confirmed_at`、`pending_count_current`、`confirmed_count_current`、`synced_total`、`synced_fund_count`、`note`

## 2. 估值与建议
### `GET /api/estimate`
- 参数（可选）：
  - `prefer_cached`：是否优先返回短 TTL 快照（默认 `true`）
  - `force_refresh`：是否强制实时重算（默认 `false`）
  - `incremental`：是否启用基金级增量报价复用（默认 `true`，`force_refresh=true` 时自动关闭）
- 顶层必须含：`asof`、`as_of`、`updated_at`、`confirm_state`、`buckets`、`funds`、`coverage`
- 顶层必须含：`data_status`（`status/asof/note`，`confirmed|estimating|partial`）
- 顶层建议含：`risk_overview`（风险中枢，支持前端单请求刷新）
- 顶层建议含：`cache_hit`、`cache_age_seconds`、`server_elapsed_ms`
- 顶层建议含：`incremental_mode`、`incremental_reused_quotes`、`incremental_fetched_quotes`
- `coverage` 必须含：`total`、`ok`、`failed`
- `funds[]` 必须含：
  - `fund_id`、`name`
  - `market_value_cny`、`cost_basis_cny`
  - `holding_profit_cny`、`holding_profit_rate`
  - `day_profit_cny`、`yesterday_profit_cny`
  - `yesterday_profit_source`
    - 可包含：`confirmed`、`snapshot_fallback`、`estimated_today`、`market_closed_snapshot`、`transaction_confirmed`
  - `confirm_state`（`estimated/confirmed/partial`）
  - `holding_days`、`position_weight_pct`
  - `status`、`reason`、`source`、`asof`、`as_of`、`updated_at`
  - `quote_cache_hit`、`quote_cache_age_seconds`
  - `transaction_pending_count`、`transaction_confirmed_count`（用于交易事实口径解释）
  - `market_group`（`cn_hk`/`us_overseas`）

### `GET /api/advice`
- 顶层：`date`、`actions`
- `actions[]`：`key`、`title`、`type`、`enabled`、`reason`

## 3. 执行与复盘
### `GET/POST /api/actions`
- 建议字段：`date`、`action_id`、`executed`、`amount`、`updated_at`
- 扩展字段：`occurred_at`（交易/赎回等动作的实际发生时间，ISO 8601）
- 约束：当 `occurred_at` 提供时，后端按该时间推导所属 `date`
- 顶层含：`data_status`（执行记录口径与时间说明）

### `GET /api/transactions`
- 参数：
  - `status`：`all/pending/confirmed`（默认 `all`）
  - `from`、`to`：可选，按 `occurred_at` 日期过滤（`YYYY-MM-DD`）
  - `fund_id`：可选，按基金代码过滤
  - `limit`：可选，默认 `200`
- 出参：`status`、`from`、`to`、`fund_id`、`count`、`items[]`、`summary`
- `summary`：`total_count`、`pending_count`、`confirmed_count`、`last_occurred_at`
- 顶层含：`data_status`（交易双态口径说明）

### `POST /api/transactions/import_yaml`
- 入参：`yaml`（或 `yaml_text`）字符串，内容遵循 `transactions_import.yaml` 规范
- 规范来源：`docs/交易流水YAML导入规范.md`
- 出参：`result`、`conflicts[]`、`warnings[]`、`imported_at`
- `result`：`added`、`skipped`、`conflicted`、`warnings`
- 顶层含：`data_status`

### `PATCH /api/transactions/{transaction_id}`
- 语义：手工修正交易关键字段（时间/状态/净值/份额/备注）
- 入参（可选组合，至少 1 个）：
  - `occurred_at`、`status`、`confirmed_at`
  - `amount_cny`、`nav`、`shares`、`fee_cny`
  - `note`、`audit_note`（审计备注）
- 约束：
  - `status` 仅支持 `pending/confirmed`
  - `confirmed` 状态必须有可用净值（`nav`）
  - 每次有效修正都写入 `audit_logs`（`entity_type=fund_transaction`）
- 出参：`transaction`、`changed`、`audit_logged`、`changed_fields[]`、`patched_at`
- 顶层含：`data_status`（按该基金维度返回）

### `GET /api/transactions/{transaction_id}/audit`
- 参数：`limit`（可选，默认 `20`，范围 `1-200`）
- 出参：`transaction_id`、`count`、`items[]`
- `items[]`：`id`、`actor_user_id`、`actor_username`、`entity_type`、`entity_id`、`action`、`before`、`after`、`note`、`created_at`
- 顶层含：`data_status`（审计口径说明）

### `POST /api/transactions/sync_pending`
- 语义：将 `pending` 交易按净值数据补全为 `confirmed`
- 入参：`limit`（可选，默认 500）、`fund_id`（可选，按单基金对账）
- 出参：`result`、`fund_id`、`details[]`、`synced_at`
- `result`：`total_pending`、`synced`、`skipped`、`errors`
- 顶层含：`data_status`

### `GET /api/report/daily`
- 必须字段：`summary`、`sections[]`
- `sections[]`：`title`、`lines[]`

## 4. 配置与持仓
### `GET /api/config`
- 必须字段：`holdings_count` 与会话摘要。

### `GET /api/holdings`
- 支持参数：`include_archived`
- 返回：`holdings`、`count`、`include_archived`
- 顶层含：`data_status`（默认 `confirmed`，来源数据库真源）
- `holdings[]` 建议含：`market_group`、`archived`、`archived_at`

### `POST /api/holdings`
- 最小字段：`fund_id`、`name`、`bucket`
- 语义：同用户同 `fund_id` 幂等覆盖并取消归档
- 分组规则：QDII 默认归 `us_overseas`（保留 QDII 标签）
- 顶层含：`data_status`

### `PATCH /api/holdings/{fund_id}`
- 可更新字段：`name`、`bucket`、`market_group`、`tags`、`market_value_cny`、`cost_basis_cny`、`shares`、`start_date`
- 审计要求：有效变更写入 `audit_logs`（`entity_type=holding`，含前后快照）
- 顶层含：`data_status`

### `POST /api/holdings/{fund_id}/archive`
- 语义：逻辑归档，不物理删除
- 审计要求：归档动作写入 `audit_logs`（`entity_type=holding`）
- 顶层含：`data_status`

### `GET /api/holdings/{fund_id}/audit`
- 参数：`limit`（可选，默认 `50`，范围 `1-500`）
- 出参：`fund_id`、`count`、`items[]`
- `items[]`：`id`、`entity_type`、`entity_id`、`action`、`before`、`after`、`note`、`created_at`、`actor_user_id`、`actor_username`
- 顶层含：`data_status`（审计记录口径说明）

### `POST /api/holdings/import_yaml`
- 入参：`mode`，可选 `if_empty/append/replace`
- 数据源：服务端 `config/portfolio.yaml`
- 出参：`result`（`configured_count/imported_count/skipped_count/failed_count/total_count`）
- 顶层含：`data_status`

### `GET /api/holdings/export_yaml`
- 参数：`include_archived`
- 出参：`portfolio`、`yaml`、`exported_at`
- 顶层含：`data_status`

## 5. 资料与基金目录

- 出参：`user_id`、`profile`

### `PUT /api/profile`

- 出参：同 `GET /api/profile`

### `GET /api/funds/suggest`
- 参数：`keyword`（必填）、`limit`（可选，默认 10）
- 匹配：基金代码前缀 + 名称/拼音/缩写/别名模糊
- 出参：`keyword`、`count`、`items[]`
- 顶层含：`data_status`
- `items[]`：`fund_id`、`name`、`pinyin`、`abbr`、`status`、`aliases[]`、`alias_hits[]`、`market_group`、`fund_type`、`bucket`、`tags[]`

### `GET /api/funds/search`
- 参数：`q`（可选）、`limit`（可选，默认 10）
- 匹配：基金代码/名称/拼音/简称/别名模糊
- 出参：`q`、`count`、`items[]`
- 顶层含：`data_status`
- `items[]`：`fund_id`、`name`、`pinyin`、`abbr`、`status`、`aliases[]`、`alias_hits[]`、`market_group`、`fund_type`、`bucket`、`tags[]`

### `GET /api/funds/{fund_id}`
- 出参：`fund`
- `fund`：`fund_id`、`name`、`pinyin`、`abbr`、`status`、`aliases[]`、`market_group`、`fund_type`、`bucket`、`tags[]`、`source`、`updated_at`
- 顶层新增：`performance_ranges`（收益区间统计）
  - `d7/d30/d90/d180/d365/ytd`：`available`、`return_pct`、`from_trade_date`、`to_trade_date`
- 顶层新增：`integrity`（完整性标记）
  - `status`（`complete/partial/missing`）、`history_days`、`latest_trade_date`、`latest_confirm_state`
  - `recent_30d_coverage`、`recent_30d_expected_days`、`recent_30d_available_days`
- 顶层新增：`anomalies[]`（异常点标识）
  - `type`、`severity`、`message`
  - 可选：`trade_date`、`change_pct`、`latest_trade_date`、`states[]`
- 顶层含：`data_status`

### `GET /api/funds/{fund_id}/nav/latest`
- 出参：`fund_id`、`available`、`latest`
- `latest`：`trade_date`、`estimate_nav`、`unit_nav`、`asof`、`source`、`confirm_state`
- 顶层含：`data_status`

### `GET /api/funds/{fund_id}/nav/history`
- 参数：`from`（可选，YYYY-MM-DD）、`to`（可选，YYYY-MM-DD）、`limit`（可选，默认 120）
- 出参：`fund_id`、`from`、`to`、`count`、`items[]`
- `items[]`：`trade_date`、`estimate_nav`、`unit_nav`、`asof`、`source`、`confirm_state`
- 顶层含：`data_status`

### `POST /api/funds/sync`
- 权限：管理员（API Token）
- 入参：`fund_ids`（可选，基金代码列表）、`limit`（可选，默认 120）、`async_mode`（可选，默认 `false`）
- 出参：`job`
- `job`：`job_id`、`status`、`total_count`、`success_count`、`failed_count`、`error_summary`
- `job.status`：`running/done/partial/failed`
- `job` 扩展字段：`log_count`、`recent_logs[]`（任务明细日志，按时间倒序）
- `recent_logs[]`：`id`、`job_id`、`fund_id`、`status`、`attempts`、`message`、`source`、`asof`、`created_at`
- `recent_logs[].status`：`job_scheduled/success/fetch_exception/quote_unavailable/quote_format_invalid/nav_missing/persist_failed`
- 顶层含：`data_status`

### `GET /api/funds/sync/jobs/{job_id}`
- 权限：管理员（API Token）
- 出参：`job`（同上，含 `log_count/recent_logs[]`）
- 顶层含：`data_status`

## 6. 设置与测速
### `GET /api/settings`
- 出参：`settings`、`user_id`
- `settings.notifications` 建议包含：`feishu`、`telegram`、`email`
- `settings.notifications.feishu` 建议字段：`enabled`、`webhook_url`、`advice_time`、`report_time`、`timeout_seconds`、`retry_times`、`template`
- `settings.notifications.feishu.timeout_seconds` 建议范围：`0.5-30.0`（秒）
- `settings.notifications.feishu.retry_times` 建议范围：`0-5`（整数）
- `settings.notifications.feishu.template` 建议枚举：`title_content_metadata`、`content_only`
- `settings.notifications.telegram` 建议字段：`enabled`、`bot_token`、`chat_id`、`parse_mode`、`disable_web_page_preview`、`timeout_seconds`、`retry_times`

### `PUT /api/settings`
- 入参：`settings`（对象）
- 出参：`settings`、`user_id`

### `PUT /api/settings/notifications/feishu/webhook`
- 入参：`webhook_url`（字符串，去首尾空白后不能为空）
- 语义：独立更新飞书 webhook 凭据，避免通过 `PUT /api/settings` 全量回传敏感字段。
- 出参：`user_id`、`updated`、`credential`、`notifications.feishu`（仅非敏感配置，不回显 `webhook_url` 明文）
- 非法入参返回：`422 Unprocessable Entity`

### `PUT /api/settings/notifications/telegram/credential`
- 入参：`bot_token`、`chat_id`（字符串，去首尾空白后不能为空）
- 语义：独立更新 Telegram Bot 凭据，避免通过 `PUT /api/settings` 全量回传敏感字段。
- 出参：`user_id`、`updated`、`credential`、`notifications.telegram`（仅非敏感配置，不回显 `bot_token` 明文）
- 非法入参返回：`422 Unprocessable Entity`

### `POST /api/settings/notifications/telegram/test_message`
- 入参：无（读取已保存的 `bot_token/chat_id`）
- 语义：发送固定测试消息，用于本地/联调一键验证 Telegram 凭据与 `chat_id` 是否可用。
- 出参（成功）：`user_id`、`ok=true`、`sent=true`、`trace_id`、`provider_message_id`、`attempts`、`max_attempts`
- 出参（失败）：`user_id`、`ok=false`、`sent=false`、`trace_id`、`error`（含 `category/http_status/error_code/description` 或 `timeout/network_error`）、`attempts`、`max_attempts`
- 备注：响应不回显 `bot_token` 明文；若凭据缺失则返回 `422 Unprocessable Entity`

### `GET /api/settings/network-benchmark/latest`
- 出参：`user_id`、`available`、`result`
- 约束：
  - `available=false` 时 `result` 为 `null`
  - `available=true` 时 `result` 为测速结果对象
- 兼容路径：`GET /api/settings/network_benchmark/latest`（不进 schema）
- 服务路径兼容：`GET /api/network-benchmark/latest`、`GET /api/network_benchmark/latest`（历史路径）

### `POST /api/settings/network-benchmark/run`
- 入参：
  - `profile`（可选，默认 `cn_fund`，枚举：`cn_fund`、`global`）
  - `timeout_seconds`（可选，默认 `6.0`，范围：`0.5-12.0`）
  - `persist`（可选，默认 `true`）
- 出参：`user_id`、`result`
- 兼容路径：`POST /api/settings/network_benchmark/run`（不进 schema）
- 服务路径兼容：`POST /api/network-benchmark/run`、`POST /api/network_benchmark/run`（历史路径）
- 非法入参返回：`422 Unprocessable Entity`

## 7. 错误返回
- 全部 API 响应头包含 `X-Request-ID`（客户端未传时由服务端生成，可用于链路日志关联）。
- 全部中文错误信息。
- 包含可定位字段（`detail/reason`）。
- 外部源故障优先降级，不直接全量失败。
- 响应头建议返回：`X-Request-ID`（用于前后端联调与日志关联）。

## 8. Gate-C 验收用例固化（口径一致 + 降级不阻断）
- 验收脚本：`python scripts/check_gate_c.py`
- 一键验收：`python scripts/check_gate_c_full.py`
- 用例与通过标准：
  1. `/api/estimate` 必须返回 `coverage.total/ok/failed`。
  2. 满足 `coverage.total = coverage.ok + coverage.failed`。
  3. 当存在失败基金时，失败项必须包含 `reason` 字段。
  4. 即使部分基金估值失败，`/api/advice` 与 `/api/report/daily` 仍返回 200。
  5. 以上检查通过即可视为 Gate-C 验收通过。
