# VectorControl 架构说明

本文档用于快速理解项目架构，适合作为 AI 上下文输入。

## 1. 系统定位与边界
### 1.1 定位
- 项目类型：个人投资决策工作台
- 核心目标：把「估值 -> 指令 -> 执行 -> 复盘」做成可解释、可审计、可回滚的流程
- 非目标：不做短线预测，不做情绪化资讯流，不提供自动交易

### 1.2 核心约束
- 多用户数据隔离：所有业务数据按 `user_id` 隔离
- 接口向后兼容：核心接口只增字段，不删字段，不改字段语义
- 失败可降级：单基金失败不阻断页面主流程

## 2. 整体架构
```text
Browser (React)
   |
   |  HTTP(S) /api/*
   v
Nginx (生产) / Vite(开发)
   |
   v
FastAPI (backend/app/main.py)
   |
   +--> Router Layer (api/routers/*)
   +--> Domain Logic (estimator/risk/policy/data_sources)
   +--> Storage Layer (storage/db.py)
   |
   v
SQLite(本地) / PostgreSQL(生产推荐)
```

## 3. 后端分层（FastAPI）
### 3.1 入口层
- 文件：`backend/app/main.py`
- 职责：
  - 应用初始化
  - 认证中间件（会话 token 与 admin token 兼容）
  - 路由挂载
  - 启动时加载配置并初始化数据库

### 3.2 路由层
- 目录：`backend/app/api/routers/`
- 主要路由：
  - `auth.py`：登录/注册/会话
  - `holdings.py`：持仓查询与更新
  - `estimate.py`：估值结果
  - `risk.py`：风险概览
  - `advice.py`：当日策略动作
  - `actions.py`：执行记录写入/读取
  - `report.py`：日报复盘
  - `config.py`、`settings.py`、`funds.py`、`profile.py`
- 规则：路由层只做参数校验与编排，复杂逻辑下沉到业务模块

### 3.3 业务模块
- `estimator/`：估值聚合、持仓指标口径统一
- `risk/`：风险指标和覆盖率汇总
- `policy/`：策略规则（固定动作 + 条件动作）
- `data_sources/`：外部数据源抓取、超时控制、回退逻辑

### 3.4 存储层
- 文件：`backend/app/storage/db.py`
- 已管理表（核心）：
  - `user_accounts`、`user_sessions`
  - `holdings`
  - `actions_log`
  - `estimate_snapshot`
  - `user_settings`
  - `user_profiles`
  - `fund_catalog`
  - `fund_profit_confirm`

## 4. 前端分层（React + Vite）
### 4.1 入口与状态
- `frontend/src/App.jsx`：页面主容器与路由态（Tab）
- `frontend/src/hooks/useAuth.js`：登录态与会话初始化
- `frontend/src/hooks/usePortfolio.js`：持仓、估值、设置、刷新状态

### 4.2 组件层
- 目录：`frontend/src/components/`
- 关键组件：
  - `TopToolbar.jsx`：顶部状态与全局动作
  - `SummaryCards.jsx`：总览指标
  - `HoldingsTable.jsx`：持仓主表
  - `FundDetailPanel.jsx`：基金详情与图表
  - `LoginPanel.jsx`：登录/注册
  - `SettingsDrawer.jsx`：用户设置
  - `RiskCenter.jsx`、`BottomTabs.jsx`、`FeedbackState.jsx`

### 4.3 API 访问
- 文件：`frontend/src/api.js`
- 约定：
  - 默认同域 `'/api'`
  - 自动携带 `Authorization: Bearer <token>`
  - 统一错误解析并抛出业务可读 message

## 5. 数据流与关键链路
### 5.1 登录链路
1. 用户提交账号密码到 `/api/auth/login`
2. 后端返回 `token + user`
3. 前端写入本地 token 并调用 `/api/auth/me` 校验会话
4. 进入工作台并加载持仓/估值/设置

### 5.2 刷新链路
1. 前端调用 `/api/estimate`
2. 后端按 `user_id` 读取持仓
3. 调用外部源获取基金数据（超时 + 回退）
4. 返回 buckets + funds + coverage + asof + confirm_state
5. 前端更新首页、持仓表、详情图和风险中心

### 5.3 执行与复盘链路
1. 用户执行动作 -> `/api/actions` 写入
2. 页面读取执行记录并更新待办
3. `/api/report/daily` 生成日报摘要和分段内容

## 6. 配置与真源策略
- `config/*.yaml` 用途：
  - 初始化导入
  - 备份导出
- 运行态真源：
  - 数据库（持仓、执行、快照、设置、用户资料）
- 原则：
  - 前端 CRUD 不直接改 YAML
  - 通过 API 写数据库

## 7. 部署架构
### 7.1 生产推荐
- `deploy/docker-compose.prod.yml`
- 容器：
  - `nginx`（80/443，对外入口）
  - `backend`（内部网络）
  - `postgres`（内部网络）
  - `frontend-build`（构建静态资源）

### 7.2 HTTPS
- Let’s Encrypt + certbot
- 脚本：
  - `scripts/deploy_prod.sh`
  - `scripts/renew_cert.sh`
  - `scripts/update_prod.sh`
  - `scripts/backup_db.sh`

### 7.3 部署验收
- `scripts/check_gate_d.py`
- 最小检查：
  - 首页 200
  - `/api/healthz` 200
  - 未登录访问受保护接口返回 401
  - Compose 核心服务运行

## 8. 质量门禁（Gate）
- Gate-A：本地可复现启动与核心 API 通
- Gate-B：接口契约稳定与回归
- Gate-C：外部源失败降级可视化
- Gate-D：生产部署闭环（Compose + Nginx + HTTPS）

## 9. 分支与协作
- `dev`：开发与集成
- `main`：发布与生产
- 文档、ROADMAP 与代码必须同步更新
