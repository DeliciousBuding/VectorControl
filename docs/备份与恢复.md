# 备份与恢复手册 (Runbook)

本文档描述 VectorControl 系统的备份与恢复流程，适用于生产环境（Linux/Docker）与开发环境（Windows/Local）。

## 1. 数据资产清单

系统核心数据包含：

1. **SQLite 数据库**: 存储所有业务数据（用户、持仓、交易、设置）。
   - 路径：`backend/data/app.db`
2. **配置文件**:
   - `config/*.yaml` (基金列表、策略配置、组合配置)
   - `.env` (环境变量、密钥)

## 2. 备份流程

### 2.1 SQLite 热备份 (推荐)

SQLite 支持在线备份，无需停止服务。

**Docker 环境 (生产):**

```bash
# 假设容器名为 vectorcontrol-backend-1
# 备份到宿主机当前目录
docker exec vectorcontrol-backend-1 sqlite3 /app/data/app.db ".backup '/app/data/app.db.bak'"
docker cp vectorcontrol-backend-1:/app/data/app.db.bak ./backup_$(date +%Y%m%d_%H%M%S).db
```

**Windows 开发环境:**

```powershell
sqlite3 backend/data/app.db ".backup 'backend/data/app.db.bak'"
copy backend/data/app.db.bak backups/backup_$(Get-Date -Format "yyyyMMdd_HHmmss").db
```

### 2.2 配置文件备份

配置文件变更频率较低，建议纳入 Git 版本控制。生产环境特有的 `.env` 文件需单独备份。

```bash
cp .env ./backup_env_$(date +%Y%m%d)
```

### 2.3 自动化备份 (Cron 示例)

建议每日凌晨执行备份。

**Linux Crontab:**

```bash
# 编辑 crontab
crontab -e

# 添加以下行 (每天凌晨 3:00 备份数据库)
0 3 * * * docker exec vectorcontrol-backend-1 sqlite3 /app/data/app.db ".backup '/app/data/backup_daily.db'" && docker cp vectorcontrol-backend-1:/app/data/backup_daily.db /path/to/backups/db_$(date +\%Y\%m\%d).db
```

## 3. 恢复流程

### 3.1 恢复前准备

1. **停止服务**: 防止写入冲突。
   ```bash
   docker-compose down
   # 或只停止后端
   docker-compose stop backend
   ```
2. **备份当前数据**: 即使是坏数据，也建议先归档，以防误操作。
   ```bash
   cp backend/data/app.db backend/data/app.db.corrupted
   ```

### 3.2 执行恢复

**覆盖数据库文件:**

```bash
# 将备份文件覆盖回数据目录
cp /path/to/backups/backup_20231001.db backend/data/app.db
```

**Docker Volume 恢复:**

如果使用了 Docker Volume (如 `postgres_data`，虽然当前项目主要用 SQLite，但若迁移需注意)，需使用临时容器挂载恢复。

对于 SQLite (Bind Mount 模式):
直接替换宿主机映射的 `app.db` 文件即可。

### 3.3 验证清单 (Smoke Test)

恢复后，启动服务并检查以下项目：

1. **服务启动**: Check `docker-compose logs -f backend` 无报错。
2. **登录**: 使用原有账号尝试登录。
3. **资产数据**: 确认首页 "总资产" 数值是否符合预期。
4. **交易记录**: 检查最近一笔交易是否存在。
5. **系统状态**: 访问 `/system/status` (API) 或前端 "关于" 页面确认版本与状态。

## 4. 灾难恢复 (Disaster Recovery)

若服务器完全损毁：

1. **准备新环境**: 安装 Docker, Git。
2. **拉取代码**: `git clone ...`
3. **恢复配置**: 将备份的 `.env` 放回 `deploy/` 或根目录。
4. **恢复数据**: 将备份的 `app.db` 放回 `backend/data/`。
5. **启动服务**: `docker-compose up -d --build`。

---

**注意**: 定期（如每月）进行一次恢复演练，确保备份文件有效且恢复流程可行。
