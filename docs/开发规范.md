# 开发规范

## 1. 目标

本规范用于统一 `VectorControl` 的研发协作方式，确保项目具备可复现、可维护、可交接的工程质量。

## 2. 语言与编码规范

- 文档统一中文：`README.md`、`docs/*`、脚本说明、变更说明。
- 提交信息统一中文。
- 代码注释、日志提示、错误提示优先中文。
- 保留英文的范围仅限：API 字段名、第三方库名、协议标准术语。
- 所有文本文件统一 `UTF-8`（建议无 BOM）。
- Windows 终端若出现乱码，先执行：`chcp 65001`。

## 3. 分支与协作规范

- 推荐分支：
  - `backend-milestones`：后端里程碑开发。
  - `frontend-milestones`：前端里程碑开发。
  - `data-config`：配置与数据维护。
  - `integrate-main`：集成联调与发布准备。
- 每个角色只提交本职路径，禁止夹带无关改动。
- 合并顺序建议：后端 -> 前端 -> 数据配置。

## 4. 提交规范

- 提交信息必须为中文，建议前缀：`功能`、`修复`、`文档`、`测试`、`杂务`。
- 单次提交应聚焦单一目标。
- 合并提交也使用中文，例如：`合并分支：后端里程碑到集成主线`。
- 建议启用：
  - `git config core.hooksPath .githooks`
  - `git config commit.template .gitmessage-zh.txt`

## 5. 编码与注释规范

- 注释应解释“为什么这样做”，避免翻译式注释。
- 外部数据源逻辑必须写清主源与回退策略。
- 新增接口需说明输入、输出、失败行为。

## 6. 外部数据源规范

- 每个外部请求必须设置超时。
- 主源失败必须有回退策略。
- `/api/estimate` 的 `funds` 至少包含：
  - `status`：`ok` 或 `failed`
  - `reason`：失败原因
  - `source`：数据来源
  - `asof`：估值时间
- 单只基金失败不能影响其余基金与分桶聚合。

## 7. 测试规范

- 外部数据源变更必须补最小回归测试。
- 至少覆盖：
  - 主源成功
  - 主源失败后回退成功
  - 部分基金失败但分桶仍可计算
- 每次提交前执行最小自测并记录结果。

## 8. 启动规范（Windows）

- 后端通过 `scripts/start_backend.bat` 启动。
- 前端通过 `scripts/start_frontend.bat` 启动。
- 新机器 5 分钟内应完成最小跑通：
  - `http://127.0.0.1:21345/api/health`
  - `http://127.0.0.1:5173`

## 9. 发布前检查清单

- 提交信息是否为中文。
- `git status --short` 是否干净。
- 以下接口是否可用：
  - `/api/health`
  - `/api/config`
  - `/api/estimate`
  - `/api/advice`
  - `/api/actions`
  - `/api/report/daily`
