# 开发规范（VectorControl）

## 1. 基础规范
- 文档、注释、日志、错误提示、提交信息统一中文。
- 文本文件统一 UTF-8（无 BOM）。
- 禁止提交运行产物：`__pycache__/`、`*.db`、`node_modules/`、临时日志。

## 2. 架构边界
### 2.1 后端
- `main.py` 仅做应用初始化与路由注册。
- 路由按领域放在 `backend/app/api/routers/`。
- 数据访问集中在 `backend/app/storage/`，路由层不得直接拼 SQL。
- 外部源访问集中在 `backend/app/data_sources/`，必须可超时与可回退。

### 2.2 前端
- 页面编排放 `App.jsx`；业务逻辑放 `hooks/`；渲染组件放 `components/`；纯工具放 `utils/`。
- 页面文案必须面向用户，不显示开发术语。
- 图表统一支持中轴虚线（0% 或成本线）。

## 3. 数据真源与配置规则
- 运行态真源：SQLite。
- YAML 仅用于导入初始化与导出备份。
- 前端不得直接写 YAML；所有写操作走后端 API。

## 4. API 契约规则（Gate-B）
- 核心接口：`/api/estimate`、`/api/advice`、`/api/actions`、`/api/report/daily`、`/api/config`。
- 契约冻结原则：允许新增字段；禁止删除字段、修改字段语义。
- `/api/estimate` 每个基金项必须有：`status`、`reason`、`source`、`asof`。
- 异常响应必须是可读中文，包含可定位信息。

## 5. 降级与稳定性规则（Gate-C）
- 外部请求必须设置超时（建议 2-4 秒）。
- 主源失败必须走回退源；单基金失败不得中断全量估值。
- 聚合结果必须返回覆盖率字段（建议 `coverage.total/ok/failed`）。

## 6. 测试与验收
- 后端每次提交前至少通过：
  - `python -m compileall backend/app`
  - 核心接口烟测：`/api/health`、`/api/config`、`/api/estimate`
- 前端每次提交前至少通过：`npm run build`。
- 集成合并前必须完成 Gate-A/B/C 验收清单。

## 7. 代码评审要点
- 是否破坏接口向后兼容。
- 是否违反“SQLite 真源”原则。
- 是否引入未降级的外部依赖点。
- 是否夹带跨职责目录改动。
