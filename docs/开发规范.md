# 开发规范（VectorControl）

## 1. 基础规则
- 文档、注释、日志、错误信息、提交信息全部中文。
- 普通提交标题格式必须为：`前缀: 一句话说明`（支持 `:` / `：`，且冒号后必须有空格）。
- 允许中文前缀：`功能`、`修复`、`优化`、`重构`、`文档`、`测试`、`构建`。
- 禁止英文前缀：`feat`、`fix`、`docs`、`chore`、`refactor`、`test`、`style`、`perf`、`build`、`ci`、`revert`。
- 发布提交标题格式：`发布: vX.Y.Z - 一句话摘要`，正文必须包含 `新增/修复/优化/文档` 四段。
- 文本文件统一 UTF-8（无 BOM）。
- 文档中的更新时间统一格式：`更新时间：YYYY-MM-DD HH:MM:SS`，必须填写真实系统时间，不得附加说明文本。
- 禁止提交运行产物：`__pycache__/`、`*.db`、`node_modules/`、临时日志。
- `ROADMAP.md` 任务状态统一使用 `[ ]` 与 `[√]`，完成即打钩并注明负责人。

## 2. 架构边界
### 2.1 后端
- `main.py` 只负责应用初始化、中间件、路由注册。
- 路由在 `backend/app/api/routers/` 按领域拆分。
- 数据访问集中到 `backend/app/storage/`，路由层不拼 SQL。
- 外部源集中到 `backend/app/data_sources/`，必须有超时和回退。

### 2.2 前端
- `App.jsx` 只做页面编排；业务逻辑放 `hooks/`；渲染组件放 `components/`；计算工具放 `utils/`。
- 页面文案必须是用户语言，不暴露开发术语。
- 登录、刷新、设置、交易四条主链路的错误提示必须包含“下一步”指引，避免只显示技术错误文本。
- 图表必须有中轴虚线（0% 或成本线），颜色遵循涨红跌绿。
- 导航固定为 5 Tab（首页/自选/交易/持仓/我的），不得出现临时调试入口。
- 详情查看时必须保持全局汇总信息可见（`Sticky` 顶栏或双栏固定焦点模式），避免长滚动导致决策上下文丢失。
- 持仓区上方必须提供“风险状态条”（Risk Status Bar）展示核心风险摘要，并可一键跳转到风险详情区。

## 3. 数据与权限
- SQLite 为运行真源，YAML 仅导入导出。
- 认证方案为会话令牌（Bearer Session Token）。
- 除 `/api/health` 与 `/api/auth/*` 外，所有 `/api/*` 需登录态。
- 所有业务读写必须按 `user_id` 强制隔离。
- 前端本地缓存键必须包含 `user_id`，切账号先清缓存再拉新数据。

## 4. API 契约规则（Gate-B）
- 核心接口：`/api/estimate`、`/api/advice`、`/api/actions`、`/api/report/daily`、`/api/config`、`/api/holdings`。
- 契约冻结原则：只允许新增字段，不允许删除字段或改变既有语义。
- `/api/estimate` 基金项必须含：`status`、`reason`、`source`、`asof`。
- 核心聚合接口应统一返回 `data_status`（`status/asof/note`），用于解释数据口径与新鲜度。
- 系统自省接口固定为 `GET /api/system/status`，用于输出版本、commit、数据源健康与任务最近运行状态。
- 交易导入统一遵循 `docs/交易流水YAML导入规范.md`，禁止私自扩展字段语义而不同步文档。
- 错误响应统一中文，带可定位字段（`detail/reason`）。

## 5. 设计系统落地规则
- 颜色、字号、间距、圆角、阴影必须来自设计 Token，禁止组件私有魔法值。
- 数字类字段使用等宽数字（`tabular-nums`）。
- 关键路径必须有加载态、空状态、错误态。
- 首页与持仓为任务流，不做资讯瀑布流。
- 面积图不得以装饰为主，优先保证数据对比度与可判读性，避免过重渐变噪音。
- 持仓列表 `Mini-Sparkline` 必须标注时间跨度（如 `02.01-02.06`），并遵循红/绿/灰统一语义色。
- 收益率图默认显示 `0%` 基准虚线；净值/收益图需显示成本参考虚线（与主线可明显区分）。

## 6. 交互与状态可追溯
- 当日收益等关键字段必须区分“估算”与“已确认”状态：
  - 估算态：显示 `Estimating`（或等价中文提示）与动态状态标识。
  - 确认态：显示 `Confirmed`（或等价中文提示）与静态确认标识。
- 关键状态必须可解释：用户需能识别当前数据口径与更新时间，避免误判。
- 首页、持仓、交易、基金详情页必须提供“状态说明入口”（Tooltip 或状态卡），明确 `confirmed/estimating/partial` 的判定依据。
- 持仓行交互支持悬停快捷操作（`Edit` / `Audit`）。
- `Audit` 必须可查看持仓修改历史（至少包含时间、动作、变更字段）。

## 7. 稳定性规则（Gate-C）
- 外部请求必须设置超时（建议 2-4 秒）。
- 主源失败必须走回退源，单基金失败不得中断全量。
- 聚合结果返回覆盖率（`coverage.total/ok/failed`）并前端可见。

## 8. 测试与验收
- 后端提交前至少通过：
  - `python -m compileall app`
  - 核心接口烟测（health/config/estimate）。
- 前端提交前必须通过：`npm run build`。
- 合并前必须通过 Gate-A/B/C/D 清单。
- Gate-A：登录/退出/切账号/缓存隔离验收通过。
- Gate-B：首页到交易主路径可达，关键动作可闭环。
- Gate-C：口径一致且外部源故障可降级。
- Gate-D：VPS 部署可复现（HTTPS、容器状态、数据库不公网暴露）。
- 发布到 `main` 前必须完成文档全量巡检（至少覆盖 `README.md`、`ROADMAP.md`、`docs/架构说明.md`、`docs/开发规范.md`、`docs/接口契约.md`、`docs/交易流水YAML导入规范.md`、`docs/P0线上故障排查SOP.md`、`docs/状态解释验收样例.md`、`docs/最新进度.md`、`docs/Git工作流.md`、`docs/部署与运行.md`），并在发布说明写明 `文档` 小节。
- 发布前必须执行：`python scripts/check_docs_gate.py`。
- 发布前建议统一执行：`python scripts/check_release_preflight.py`（默认串行执行 `check_docs_gate --strict`、`compileall backend/app`、`npm --prefix frontend run build`）。
- `check_docs_gate.py` 必须同时校验：核心文档、发布模板、文档范围一致性、关键门禁文件（含 `scripts/check_release_preflight.py`、`.githooks/*`、`.github/workflows/*`）以及核心文档更新时间格式/时间合法性。
- push 前必须通过 `.githooks/pre-push`（自动执行 `python scripts/check_docs_gate.py --strict`）。
- PR 到 `dev/main` 必须通过 `.github/workflows/docs-gate.yml`（`--strict --diff-base`）。
- 分支保护基线检查（管理员）：`python scripts/branch_protection.py --mode check --required-contexts "Docs Gate / docs-gate" --main-required-contexts "Release Consistency / verify-release"`。
- commit-msg 必须通过 `.githooks/commit-msg`（自动执行 `python scripts/check_release_message.py`）。
- `main` 发布后必须通过：`python scripts/check_main_release.py --commit HEAD --check-remote-tag --remote origin`。
- 前端性能验收新增：
  - 持仓数量 `50+` 时滚动与刷新无明显卡顿。
  - 高频刷新场景（如 `30s/次`）列表渲染应避免全量重绘。
- 状态解释验收新增：
  - `data_status` 必须在关键聚合接口可见且字段完整。
  - `/system/status` 页面可访问且能展示最近一次同步与对账时间。

## 9. 前端工程实现约束
- `recharts` 公共配置需抽象到统一文件（建议：`frontend/src/utils/chartConfigs.js`），禁止图表样式散落重复定义。
- 持仓列表与高频刷新组件优先使用 `React.memo`、`useMemo`、`useCallback` 控制不必要重渲染。
- 新增图表或状态组件时，必须复用统一 Tooltip、动画时长、颜色 Token。

## 10. 评审重点
- 是否破坏多用户隔离。
- 是否破坏接口兼容性。
- 是否违反设计 Token 体系。
- 是否夹带越权目录改动。
- 是否破坏“汇总常驻可见 + 风险状态前置”的信息架构约束。
- 是否遗漏“估算/确认”状态区分与可追溯提示。

## 11. 生产部署规则（Gate-D）
- 生产编排统一使用 `deploy/docker-compose.prod.yml`。
- 只允许 Nginx 暴露 `80/443`，后端与数据库仅容器内通信。
- 证书签发与续期统一走 `scripts/deploy_prod.sh` 与 `scripts/renew_cert.sh`。
- 生产验收统一执行 `python scripts/check_gate_d.py`。
