# 开发规范（VectorControl）

## 1. 语言与编码

- 文档、注释、日志、错误提示、提交信息统一中文。
- 文本文件统一 `UTF-8` 编码。
- Windows 终端建议执行 `chcp 65001` 以避免乱码。

## 2. 架构解耦规范

### 2.1 前端（解耦要求）

- `App.jsx` 只负责页面编排与状态汇总。
- 业务逻辑放入 `hooks/`，禁止在组件内堆积请求逻辑。
- 视图拆分到 `components/`，单组件职责单一。
- 工具函数放入 `utils/`，禁止重复格式化逻辑。
- 页面文案必须是面向用户的中文，不展示开发术语。

### 2.2 后端（解耦要求）

- `main.py` 只保留应用初始化、中间件与路由注册。
- 接口按领域拆分到 `backend/app/api/routers/`。
- 共用依赖（用户态、配置读取、日期工具）放到 `backend/app/api/deps.py`。
- 数据读写集中在 `backend/app/storage/`，路由层不直接拼 SQL。

## 3. 接口与数据约定

- `GET /api/estimate` 必须返回：`asof`、`funds`。
- `funds[]` 至少包含：
- `fund_id`
- `name`
- `market_value_cny`
- `cost_basis_cny`
- `holding_profit_cny`
- `estimate_pct`
- `status`
- `reason`
- `source`
- 数据状态需区分“估算值”和“确认值”（后续里程碑实现）。

## 4. 质量门槛

- 前端每次提交前执行：`npm run build`。
- 后端每次提交前至少执行：`/api/health`、`/api/estimate` 自测。
- 涉及外部数据源时，必须有超时与回退策略。

## 5. 提交规范

- 提交信息使用中文。
- 每次提交只做一类变更（功能、修复、文档分开）。
- 禁止把运行产物纳入提交（`__pycache__`、`*.db`、`node_modules`）。

## 6. 分支职责

- `dev`：日常开发与集成。
- `main`：稳定发布版本。
- `backend-milestones`：后端并行开发。
- `frontend-milestones`：前端并行开发。
- `data-config`：配置数据专项变更。

详细合并流程见 `docs/Git工作流.md`。
