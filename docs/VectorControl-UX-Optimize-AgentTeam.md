# VectorControl UX 优化 Agent Team 设计任务

## 项目背景

VectorControl 是一个面向个人投资决策的全栈系统，核心目标是把"数据获取 -> 估值汇总 -> 动作建议 -> 执行记录 -> 日报复盘"做成可审计、可回放、可部署的闭环。

- **前端技术栈**：React + Vite
- **后端技术栈**：FastAPI + PostgreSQL
- **当前状态**：已完成基础功能（登录、持仓、交易、基金详情、收益图表、基准对比、定投计划等），处于持续迭代优化阶段
- **设计规范**：参考 `docs/设计系统与交互规范.md`
- **产品需求**：参考 `docs/产品需求与页面蓝图.md`

## 任务目标

创建一个针对 VectorControl 项目的 UX/前端优化 Agent Team，从不同角度分析并提出改进建议。

## Agent Team 成员与职责

---

### Agent 1: UX 体验设计师 (UX Expert)

**角色定位**：关注用户交互体验、信息架构、视觉层次

**分析维度**：

1. **信息架构审视**
   - 当前页面结构和导航是否清晰？
   - 关键信息层级是否合理？
   - 用户能否在3秒内找到核心功能？

2. **交互体验分析**
   - 交易流程是否足够简洁（当前"详情到下单成功不超过3次点击"）？
   - 各种状态反馈（加载、空数据、错误）是否友好？
   - 表单填写体验是否流畅？

3. **视觉层次优化**
   - 颜色使用是否一致（当前"涨跌默认红涨绿跌"）？
   - 关键数据是否突出显示？
   - 是否存在视觉噪音？

4. **动效与反馈**
   - 当前过渡时长（150-220ms）是否合理？
   - 骨架屏体验是否完整？
   - 图表交互是否流畅？

5. **移动端适配审视**
   - 当前移动端适配是否完善？
   - 触摸区域是否足够大？
   - 关键操作是否容易触达？

**输出要求**：
- 识别 3-5 个当前最影响用户体验的问题
- 提出具体的改进方案（可附带草图或描述）
- 推荐优先优化点

---

### Agent 2: 前端架构师 (Frontend Architect)

**角色定位**：关注代码质量、性能优化、可维护性、技术债务

**分析维度**：

1. **代码质量审视**
   - 组件是否遵循单一职责原则？
   - 是否有重复代码可以提取？
   - 状态管理是否清晰？

2. **性能优化空间**
   - 首屏加载时间（当前"3秒骨架、5秒资产卡"）能否进一步优化？
   - 是否有不必要的重渲染？
   - 图表库使用是否最优？

3. **技术债务评估**
   - 是否有遗留的硬编码？
   - 样式管理是否一致（当前使用 tokens.css）？
   - 测试覆盖是否充分？

4. **可维护性分析**
   - 组件文档是否完整？
   - 命名是否清晰一致？
   - 代码是否有适当的注释？

5. **依赖管理**
   - 依赖是否都是必需的？
   - 是否有安全漏洞？
   - 打包体积是否需要优化（当前有 chunk >500kB 警告）？

**输出要求**：
- 识别 3-5 个技术优化点
- 提出具体的技术改进方案
- 评估改进的投入产出比

---

### Agent 3: 产品体验官 (Product Advocate)

**角色定位**：从用户视角质疑功能合理性、寻找体验盲点

**分析维度**：

1. **功能必要性质疑**
   - 每个功能真的被需要吗？
   - 是否有"看起来有用但没人用"的功能？
   - 哪些功能可以简化或合并？

2. **边缘情况检查**
   - 网络异常时用户体验如何？
   - 数据不完整时如何展示？
   - 大数据量场景（持仓100+基金）表现如何？

3. **竞品对标**
   - 主流基金APP的核心体验是什么？
   - 有哪些优秀实践可以借鉴？
   - 差异化优势在哪里？

4. **认知负荷分析**
   - 新用户能否快速理解系统？
   - 专业术语是否需要解释？
   - 引导流程是否足够？

5. **闭环完整性**
   - 每个功能是否都有"下一步"？
   - 错误状态是否提供解决方案？
   - 成功操作后是否有正向反馈？

**输出要求**：
- 提出至少5个用户体验盲点
- 对每个问题评估严重程度
- 推荐"不应该做"的特性

---

## 协作要求

1. **独立分析**：每个 Agent 独立完成自己的分析，从不同视角审视
2. **参考现有规范**：所有分析必须基于现有设计系统（tokens.css）和产品需求
3. **可行性优先**：建议必须可落地，不能是空想
4. **最终整合**：由协调者汇总三个 Agent 的输出，形成可执行的任务清单

## 输出格式

```
## UX 体验分析
[Agent 1 的输出 - 关注交互、信息架构、视觉层次]

## 前端技术分析
[Agent 2 的输出 - 关注代码质量、性能、技术债务]

## 产品体验审视
[Agent 3 的输出 - 关注盲点、边缘情况、认知负荷]

## 整合优化建议
[协调者的整合输出，按优先级排序的可执行任务清单]
```
