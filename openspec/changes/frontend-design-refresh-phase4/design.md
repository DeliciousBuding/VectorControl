## 设计目标

本轮在 phase1 / phase2 / phase3 之后，继续做两件事：

1. **让设置抽屉先给摘要，再给配置细节**：参考 Ant Design 的 Data Entry / Drawer 节奏，以及 GitHub Primer 表单和设置页的分层原则，先展示关键状态摘要，再进入每个配置分组。
2. **让抽屉头部、正文和页脚成为同一套视觉系统**：接通 `Drawer` 面板样式，统一头部标题、副标题、页脚操作区和卡片表面的视觉语言。

## 设计原则

### 1. 摘要优先
- 打开设置中心后，用户应先看到自动刷新、定投计划、通知通道等关键摘要。
- 摘要卡只读取现有状态，不引入新的业务逻辑。

### 2. 分区标题要带说明
- 常用设置、网络与诊断、消息推送三个区块要有更明确的图标和说明文字。
- 用户不必进入每个设置组也能先理解该分区负责什么。

### 3. 保持交互零回归
- 不重写表单逻辑，不改变按需加载与保存逻辑。
- 测试应继续覆盖打开、按需加载、保存与通知诊断路径。

## 非目标

- 本轮不重构设置 schema。
- 本轮不改任何后端接口和保存 payload。
- 本轮不引入复杂动画或分页式设置流程。
