## 为什么

首页主路径与设置中心已经基本进入统一的摘要式产品语言，但 dev-only 的 `DiagnosticsPanel` 仍停留在“黄底提示条 + 两个按钮 + 一段预格式文本”的原始调试样式。它虽然不直接面向最终用户，却是开发与排障链路里最常被打开的入口之一，当前的视觉层级已经明显落后于其他面板。

当前最直接的问题有三类：

1. 标题、动作和内容都挤在一条简单横栏里，缺少状态摘要和上下文说明。
2. 空态、成功态与复制态都没有清晰区分，只能依赖按钮文字判断当前状态。
3. 调试区与首页现有卡片语言不一致，影响开发环境整体质感。

## 变更内容

1. 建立 `frontend-design-refresh-phase15` 变更入口。
2. 聚焦 `DiagnosticsPanel`，为其补齐摘要头部、状态卡、空态 / 错误态与诊断文本容器。
3. 新增最小测试，覆盖开发环境渲染、诊断拉取复制和生产环境不渲染三类行为。

## 影响

- 让 dev-only 诊断区也纳入当前统一的前端语言体系。
- 提升开发与排障时的可扫读性，不改变 `/api/system/diagnostics` 调用路径。
- 保持生产环境不渲染该面板的现有约束不变。
