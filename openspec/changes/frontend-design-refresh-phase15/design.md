## 设计目标

本轮继续参考 Apple HIG 的克制信息层级、Google Material 3 的状态卡组织、GitHub Primer 的辅助面板节奏，以及 OpenAI 官网简洁区块化表达，对 `DiagnosticsPanel` 做三件事：

1. **先说明它是什么**：明确这是开发环境的诊断快照，而不是普通业务面板。
2. **先展示状态，再展示文本**：环境、数据状态、复制状态进入摘要卡，避免用户直接面对大段 `pre` 文本。
3. **让空态 / 错误态可解释**：即使尚未拉取或复制失败，也能给出下一步动作提示。

## 设计原则

### 1. dev-only 也要保持产品语言
- 调试工具不再只是粗糙提示条。
- 继续使用当前首页 / 设置中心的轻量摘要卡与柔和边框语言。

### 2. 状态优先于长文本
- 先展示“开发模式 / 待拉取 / 已复制”等状态。
- 诊断文本放在独立容器内，避免一打开就产生压迫感。

### 3. 生产环境行为不变
- `import.meta.env.PROD` 仍直接返回 `null`。
- 不扩展新的接口或调试能力。

## 非目标

- 本轮不改变 `DiagnosticsPanel` 的调用接口。
- 本轮不把 dev-only 工具暴露给生产环境。
- 本轮不改首页其他业务面板。
