## 新增需求

### 需求: 飞书 sender 必须支持发送频控
飞书 sender 必须限制同一 webhook 的过密发送，避免短时间内重复请求。

#### 场景: 相同 webhook 连续快速发送
- **当** 相同 webhook 在最小间隔内再次发送
- **那么** sender 应直接返回节流结果
- **并且** 不再发起真实 HTTP 请求

### 需求: 飞书 sender 必须支持连续失败隔离
飞书 sender 在连续失败达到阈值后，必须进入短暂隔离窗口，避免持续放大失败。

#### 场景: webhook 连续失败多次
- **当** 同一 webhook 连续失败达到阈值
- **那么** sender 进入临时隔离
- **并且** 在隔离窗口内直接返回隔离结果
