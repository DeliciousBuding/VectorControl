## 新增需求

### 需求:前端必须提供正式的构建分析入口
前端仓库必须提供明确、可执行的构建分析入口，用于支撑性能优化，而不是依赖口头约定或临时命令。

#### 场景:维护者分析前端大包来源
- **当** 维护者需要确认 `antd`、`echarts`、主包或页面级 chunk 的体积来源
- **那么** 应可通过正式脚本入口触发 `vite` 分析模式并生成构建可视化结果

### 需求:前端性能基线必须复用现有观测能力
性能优化流程必须优先复用现有指标与诊断能力，避免新建重复体系。

#### 场景:记录首屏与交互行为
- **当** 维护者需要观察首页、搜索、交易入口、资产卡更新等前端行为
- **那么** 文档必须说明如何使用 `frontend/src/utils/metrics.js` 与 `frontend/src/App.jsx` 中已有的 `recordMetric()` 埋点
- **并且** 不得破坏现有 metrics 记录格式

### 需求:性能优化文档必须给出最小验收方式
性能优化相关文档必须定义最小可执行的检查路径。

#### 场景:执行第一轮性能基线收集
- **当** 维护者开始第一轮性能优化
- **那么** 至少能够执行前端构建分析、查看本地 metrics、并结合 `/api/system/diagnostics` 与 network benchmark 输出形成基线结论
