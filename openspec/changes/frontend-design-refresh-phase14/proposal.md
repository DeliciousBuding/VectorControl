## 为什么

`SettingsDrawer` 的 `系统状态 / 通知诊断` 已在 phase12 收口，但同一页里的 `网络测速`、`飞书机器人` 与 `Telegram 机器人` 仍保留较强的“表单堆叠感”：虽然功能可用，但缺少摘要先行、动作后置、凭据独立成面的产品化层级。

当前最直接的问题有三类：

1. `网络测速` 仍主要由两个输入框、两个按钮和一段结果列表组成，摘要信息与历史状态不够显眼。
2. `飞书 / Telegram` 凭据编辑区缺少统一的通道状态、凭据状态和发送模式概览，调试时需要上下扫读多段文案。
3. 自动发现、凭据预览和参数编辑虽然完整，但仍偏“工具表单”，与当前首页 / 风险中枢 / 设置诊断区的克制摘要语言不一致。

## 变更内容

1. 建立 `frontend-design-refresh-phase14` 变更入口。
2. 聚焦 `SettingsDrawer` 的 `网络测速`、`飞书机器人` 与 `Telegram 机器人` 三段，统一头部说明、摘要卡、参数网格与凭据容器。
3. 保持现有 `data-testid`、加载逻辑、自动发现流程与保存行为不变，并补最小视觉回归锚点。

## 影响

- 让设置中心正文从“功能拼接”进一步升级为摘要优先的配置工作台。
- 继续保持现有交互契约与测试锚点稳定。
- 不扩展新的消息通道或测速能力，只收敛信息结构和视觉层级。
