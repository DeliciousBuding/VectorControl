## 设计目标

本轮继续参考 Apple HIG 的层级克制、Google Material 3 的配置摘要组织、GitHub Primer 的 page layout / form control 经验，以及 OpenAI 官网的简洁卡片表达，对 `SettingsDrawer` 正文的三段做三件事：

1. **网络测速先给配置快照**：让站点组、超时预算和最近记录状态先可扫读，再执行加载或测速动作。
2. **消息凭据先给通道摘要**：先展示启用状态、凭据状态、发送模式，再进入具体参数与凭据编辑。
3. **凭据和自动发现进入独立表面**：把 Webhook / bot_token / chat_id 的编辑、预览和下一步提示放到更安静的容器里，减少表单噪声。

## 设计原则

### 1. 摘要优先
- 用户进入设置抽屉时，应先看到当前状态，而不是直接面对多行输入控件。
- 摘要卡只回答“现在是什么状态”，动作和细节放在后面。

### 2. 参数分组明确
- 常用配置进入更规整的网格。
- 凭据、自动发现和历史结果进入独立容器，不与普通参数混排。

### 3. 行为不变
- 不改变 `benchmark-load-latest-btn`、`telegram-discovery-issue-btn` 等现有锚点。
- 不改变保存、复制、自动发现与提示逻辑。

## 非目标

- 本轮不重构 `系统状态 / 通知诊断` 区。
- 本轮不新增新的消息通道或测速字段。
- 本轮不改设置中心外的其他页面。
