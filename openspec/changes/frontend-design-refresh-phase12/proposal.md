## 为什么

风险中枢完成收口后，`SettingsDrawer` 里“系统状态 / 通知诊断”两段成为下一处最明显的高密度风格断层：抽屉头部已经是产品化设置中心，但正文里这两段仍以零散说明、按钮行和结果块拼接，缺少统一的状态摘要与操作条语言。

当前最直接的问题有三类：

1. `系统状态` 的状态信息仍以普通段落堆叠，缺少更适合排障的快照式摘要布局。
2. `通知诊断` 的通道状态、最近测试、动作按钮和测试结果仍偏“工具面板”拼接感。
3. 两段虽然逻辑完整，但缺少像 Apple / Google / OpenAI 官网那种克制、统一、低噪声的诊断工作台表达。

## 变更内容

1. 建立 `frontend-design-refresh-phase12` 变更入口。
2. 聚焦 `SettingsDrawer` 的 `系统状态` 与 `通知诊断` 两段，统一头部、状态摘要卡、工具条和结果容器。
3. 复用现有测试锚点，不改诊断逻辑；继续执行全量前端测试、analyze 与发布预检。

## 影响

- 让设置中心的诊断路径从“功能可用”升级为更一致的产品级工作台区块。
- 保持现有 test id 和行为契约稳定。
- 不改变系统状态加载、复制、测试消息和整包复制等逻辑。
