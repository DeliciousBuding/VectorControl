## 设计目标

本轮在 phase1 / phase2 之上继续做两件事：

1. **让导航成为工作台结构的一部分**：参考 Ant Design Workbench / Navigation / Layout 的“最短导航路径 + 当前项高优先级”原则，为 `SideNav` 增加当前工作区概览、分组标签与更明确的激活态。
2. **让桌面与移动导航共用一套语言**：参考 GitHub Primer 的清晰导航层级与 Saleor Dashboard 的后台导航密度控制，让 `BottomTabs` 与桌面 `SideNav` 共用配置、图标与命名口径。

## 设计原则

### 1. 共享导航源优先
- `SideNav` 与 `BottomTabs` 需要共享同一份导航配置。
- 标签、图标、分组、说明文案应从一个入口生成，避免双份定义漂移。

### 2. 当前工作区需要显式呈现
- 侧边栏顶部需要有“当前工作区”概览，帮助用户在切换页面时快速理解当前位置。
- 激活项的视觉优先级要显著高于普通项，并保持键盘 / 读屏可识别。

### 3. 移动端入口要延续桌面语义
- `BottomTabs` 不只是图标栏，也应共享桌面导航的标签与说明。
- 移动抽屉需要保留分组层级与当前项语义，避免与桌面导航断层。

## 非目标

- 本轮不重构业务路由结构。
- 本轮不新增页面级复杂动画。
- 本轮不改任何后端接口与计算逻辑。
