## 设计目标

本轮继续参考 Apple Human Interface Guidelines 对高密度任务界面的层级组织、Google Material 对数据密集工作流的摘要与操作分组方式、GitHub Primer 的 page layout 节奏，以及 OpenAI 官网的克制排版语言，完成三件事：

1. **让交易生命周期先给阶段感**：不仅展示三步，还要明确“当前正在哪里”。
2. **让交易流水先给筛选与操作秩序**：筛选、刷新、pending 对账应进入同一工具条。
3. **让状态反馈统一收口**：空态、错误态、加载态尽量复用 `SurfaceState`，避免零散提示块。

## 设计原则

### 1. 先摘要，再明细
- 生命周期和交易流水都先展示区块身份、关键摘要，再进入具体列表或表格。
- 让用户先理解上下文，再做操作。

### 2. 操作分组而非按钮堆叠
- `全部 / pending / confirmed` 作为一组筛选态。
- `刷新交易流水 / 对账 pending` 作为一组执行动作。

### 3. 状态表达低噪声统一
- 错误、空态、加载不再直接裸露为单行文案。
- 使用统一的 `SurfaceState` 保持标题、说明、hint 三层结构。

### 4. 表格保留行为，收敛表面
- 不改列结构和行为。
- 仅调整表格壳、表头、行 hover 与区块表面，提升扫描效率。

## 非目标

- 本轮不重构 `TradeCenter` 的业务逻辑。
- 本轮不调整 DCA 管理区和表格字段。
- 本轮不改 `SIPPlanManager` 内部结构，后续可单独收口。
