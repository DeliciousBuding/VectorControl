## ADDED Requirements

### Requirement: 交易生命周期与流水区应提供更强的执行上下文
交易工作台 MUST 在生命周期和流水区提供清晰的区块身份、阶段摘要和执行上下文，而不只是普通标题与按钮堆叠。

#### Scenario: 用户查看交易生命周期与流水
- **GIVEN** 用户进入交易工作台中段
- **WHEN** 页面完成渲染
- **THEN** 页面应展示交易生命周期的阶段标题、当前阶段摘要和步骤卡
- **AND** 页面应展示交易流水的摘要卡与筛选工具条

### Requirement: 交易相关状态反馈应复用统一状态语言
交易工作台 MUST 在交易流水和审计链路等高频状态面中复用统一状态组件，而不是继续使用零散占位文案。

#### Scenario: 用户遇到空态或错误态
- **GIVEN** 交易流水或审计链路没有数据、加载中或出现错误
- **WHEN** 页面渲染对应状态
- **THEN** 页面应展示统一的标题、说明和 hint 结构

### Requirement: 交易工作台中后段升级后应保持原有交互
交易工作台中后段视觉升级后 MUST 保持筛选、刷新、pending 对账、交易修正和审计查看等既有交互可用。

#### Scenario: 用户继续操作交易流水
- **GIVEN** 交易工作台中后段已升级
- **WHEN** 用户继续筛选交易、刷新列表或执行 pending 对账
- **THEN** 原有交互逻辑和前端回归测试应继续通过
