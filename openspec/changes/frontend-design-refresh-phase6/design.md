## 设计目标

本轮参考 Apple HIG 对“deference / feedback / depth”的要求、Google Material 对 loading / empty / error 的可理解反馈原则，以及 OpenAI 官网常见的克制留白和低噪声层级，继续做两件事：

1. **把状态反馈从技术占位升级为产品表面**：加载、错误和空态不再只是文本块，而是有统一图形、标题、描述和提示的表面组件。
2. **把高频状态场景先纳入统一语言**：优先覆盖首页基准区、基金详情页和风险中枢，让用户在关键路径先感受到一致的状态体验。

## 设计原则

### 1. 克制而明确
- 不做重装饰，不做夸张插画。
- 用极少的图标、留白和两层文案表达状态。

### 2. 标题 + 说明 + 下一步
- 每个状态面都应有明确标题。
- 使用一行说明告诉用户发生了什么。
- 使用 hint 告诉用户下一步可以做什么。

### 3. 保持低耦合
- 统一组件只负责状态呈现，不接管业务逻辑。
- 页面只传入状态文案和必要动作，避免组件膨胀。

## 非目标

- 本轮不重写所有历史 `chart-empty` 用法。
- 本轮不引入插画资源或复杂动效。
- 本轮不改变现有接口、按钮逻辑或页面路由。
