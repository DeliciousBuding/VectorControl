## 为什么

首页、导航、设置中心和基金详情页已经完成多轮视觉收敛，但全局 `loading / error / empty state` 仍明显偏“工程占位”：很多位置直接使用 `chart-empty` 或纯文本提示，导致状态体验缺少统一语言，也不符合 Apple / Google / OpenAI 官方产品那种克制但完整的反馈节奏。

当前直接问题有三类：

1. 加载、错误和空态缺少统一组件，不同页面的反馈样式与文案层级不一致。
2. 首页基准区、风险中枢和基金详情页这类高频区域，状态反馈仍更像技术提示，而不是产品级表面。
3. 状态提示没有形成统一的视觉语义，不利于后续继续扩展到交易、持仓和更多页面。

## 变更内容

1. 建立全局状态语言升级 phase6 的 OpenSpec 入口。
2. 新增统一的 `SurfaceState` 组件，用于加载、错误、空态和说明态。
3. 优先在首页基准区、基金详情页和风险中枢落地，保持原有交互与数据逻辑不变。

## 影响

- 让全局状态反馈更像完整产品体验，而不是临时占位。
- 为后续继续收敛 `TradeCenter`、持仓和其他子页面提供统一状态语言。
- 不改变后端接口与业务逻辑，只统一前端状态呈现。
