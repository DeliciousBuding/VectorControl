## 为什么

第一轮收口已经明确后端现有可观测性入口包括 `GET /api/system/diagnostics`、设置中心 network benchmark、以及当前发布与部署文档中的最小排障链路。但第二轮仍缺少一个专门面向“后端观测优化”的 change 入口，导致热点接口耗时、SQLite 热点查询与部署观测增强没有统一承载。

当前需要收口的重点包括：

1. 后端热点接口的耗时与错误分类还没有形成稳定的文档化治理项。
2. SQLite 作为当前真源，热点查询与持久化排障需要更明确的观测入口。
3. README / ROADMAP / 最新进度 已经提到第二轮后端观测优化，但还缺少对应 change 骨架承接。

## 变更内容

1. 建立第二轮后端观测优化 change 骨架。
2. 明确以 `GET /api/system/diagnostics`、network benchmark、部署排障链路为基础继续扩展。
3. 规定后续优化需要记录热点接口、SQLite 查询与部署观测的最小验证方式。

## 影响

- 为后端观测增强、热点接口耗时记录与部署排障收敛提供统一入口。
- 让 `ROADMAP.md`、`docs/最新进度.md` 与 OpenSpec change 保持一致引用。
- 本骨架阶段不直接变更后端代码或数据库结构。
