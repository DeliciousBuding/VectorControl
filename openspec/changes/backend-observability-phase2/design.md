## 上下文

当前仓库已经具备第一轮文档驱动收口成果：发布门禁、SOP、Gate-D 模板、`GET /api/system/diagnostics` 与 network benchmark 入口均已入库并有文档记录。与此同时，`docs/最新进度.md` 已明确第二轮将进入“后端热点接口耗时记录、SQLite 热点查询与部署可观测性增强”。

因此，第二轮后端工作需要一个独立 change，把现有观测入口与后续优化目标连起来，避免再次分散到零散文档中。

## 目标 / 非目标

**目标：**
1. 定义第二轮后端可观测性优化入口。
2. 明确热点接口、SQLite 热点查询与部署观测增强的记录范围。
3. 给出后续实现阶段最小验证与文档回写要求。

**非目标：**
1. 本骨架阶段不直接接入新的外部监控平台。
2. 本骨架阶段不替换 SQLite，也不做数据库迁移。
3. 本骨架阶段不大规模改写现有 API 契约。

## 决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 观测入口 | 先复用 `/api/system/diagnostics`、network benchmark、现有部署排障文档 | 当前仓库已存在，落地成本最低 |
| 优化重点 | 热点接口耗时、SQLite 查询热点、部署侧排障信息 | 与第二轮待办和当前真实基线一致 |
| 回写出口 | `docs/最新进度.md` + `ROADMAP.md` + 本 change | 保持进度、路线图与 OpenSpec 同步 |

## 验证策略

1. 后续实现阶段至少能对热点接口耗时记录与诊断输出做最小验证。
2. SQLite 相关热点查询或持久化排障路径需要在文档中可定位。
3. 第二轮结果应继续同步记录到 `docs/最新进度.md` 与 `ROADMAP.md`。
