## 新增需求

### 需求:后端观测优化必须复用当前仓库诊断入口
第二轮后端观测优化必须优先复用当前已经存在的诊断与排障入口，避免新建与现有文档脱节的平行体系。

#### 场景:维护者开始第二轮后端观测优化
- **当** 维护者开始推进热点接口耗时记录、SQLite 热点查询分析或部署侧排障增强
- **那么** 应先从 `openspec/changes/backend-observability-phase2/` 读取 proposal / design / tasks
- **并且** 应优先复用 `GET /api/system/diagnostics`、network benchmark 与现有部署/故障 SOP 文档

### 需求:后端观测优化必须提供最小排障验证
第二轮后端观测优化必须让维护者能够基于仓库内现有能力完成最小排障，而不是只留下实现描述。

#### 场景:维护者确认后端热点或部署异常
- **当** 维护者需要定位热点接口耗时异常、SQLite 查询热点或部署侧异常
- **那么** 应能从仓库内文档和诊断入口获得最小可执行的观察路径
- **并且** 后续结果必须同步记录到 `docs/最新进度.md` 与 `ROADMAP.md`
